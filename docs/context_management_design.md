# 模型上下文管理

完整消息继续存放在 `State.messages`、官方 PostgreSQL Checkpointer 和原始消息表。新增 `application/agents/context.py` 只构建模型输入，不删除消息、不改写用户原话、不写入长期记忆。

## 窗口与预算

统一 Planner、普通对话、补充追问和最终回答调用 `build_model_context`。保留当前用户消息，默认选取最近六个已完成的用户/助手对话轮次；孤立助手、历史系统消息和未完成旧轮次不传入。窗口设为零时只提供当前请求和必要数据。

Planner、对话和回答读取本轮召回的 `memory_context`；任务领域与操作仍需由当前用户原文支持，避免历史偏好改变本轮意图。最近推荐列表单独提供分组、编号和真实菜名，不包含整份菜谱做法。序号选择仍由确定性逻辑解析，完整推荐快照仍在 State 中。

处理过明确记忆操作的混合请求，模型读取 `state.question` 中剩余业务问题；完整原文保留在消息中。结构化检索条件仍从原文核验，不把历史消息或上下文摘要当作本轮指令。

```env
CONTEXT_RECENT_TURNS=6
CONTEXT_PLANNER_TOKEN_BUDGET=16000
CONTEXT_ANSWER_TOKEN_BUDGET=32000
```

预算单位是保守的消息长度估算：每条文本的 UTF-8 字节数加 16 的消息开销，不是模型提供商的精确 tokenizer。中文、JSON、系统提示、当前请求、记忆、推荐列表、历史和本轮证据全部计入消息预算。提供商额外注入的结构化输出 schema、协议元数据、输出 token 不包含在此估算内；配置应为这些开销留空间。日志记录节点用途、保留轮数、估算长度和预算，不记录完整消息或密钥。

超过预算先移除最旧的完整对话轮次。保护内容包括系统提示、当前请求、全部已召回记忆、推荐名称列表和必要证据，不静默截断过敏和忌口。

必要内容本身无法容纳时，抛出 `ContextBudgetExceeded`，不发送超预算的模型消息：Planner 回退规则规划；普通对话/追问请求用户缩短或拆分问题；最终回答使用完整的确定性证据格式。预算只限制上述节点的模型输入，不等同于整个业务请求大小限制。

## 检索证据压缩

最终回答有结构化 `records` 时，模型输入不重复传入同一结果的格式化 `content`。菜谱只要求推荐概要时省去 `做法/steps/procedure`，明确要求详情时保留步骤。真实来源、状态和任务要求继续传递。State 中的原始结果和兜底回答内容不受影响；证据仍过长时直接使用兜底，不截断后冒充完整答案。

## 更正、遗忘与历史

仅在明确更正或遗忘实际数据库操作成功时，ChatService 将当前用户消息 id 写入 `context_history_after`，该字段通过 Checkpointer 持久化。后续模型只读取此消息之后的已完成历史；操作本轮仍读取剩余业务问题。这样避免已删除或已更正的内容从先前用户消息、保存确认和助手回复中重新进入模型输入。

操作失败、目标歧义或未找到不会推进边界；普通新请求也不会重置已有边界。边界 id 缺失时保守地不传旧历史。最近推荐列表保留，其他仍有效的长期记忆重新召回。

这会舍弃操作之前其他对话的模型可见细节，是当前明确的设计取舍。边界按当前用户与会话隔离，不清除其他会话的旧对话、不删除原始历史；外部管理接口删除记忆不会自动更新所有会话边界。不能把它描述为全局历史遗忘。

## 已覆盖与未覆盖

本版实现统一输入入口、窗口、消息预算、证据压缩和记忆操作后的历史隔离，没有自动摘要和新增摘要模型调用。窗口之外的一般背景可能需要用户重述；推荐编号由独立快照保留，已保存偏好由长期记忆召回。完整历史仍随 State 增长，尚未优化 Checkpoint 的历史存储规模。

上下文管理版本验收时全量回归 **229 passed**，其中八项真实 PostgreSQL 集成用例。新增覆盖四类节点窗口、整轮裁剪、零窗口、受保护内容超预算兜底、原文/业务问题分离、证据概要与详情、记忆操作成功/失败边界、长对话连续选择及新连接池恢复。最新全量结果见 [固定评测设计](evaluation_design.md)。
