# Graph V2

Graph V2 keeps the original recipe, flavor, method and dish-type model, and adds canonical ingredient entities, aliases, category hierarchy, allergen provenance, culinary substitutions and dataset sources.

```text
(Dish)-[:HAS_MAIN_INGREDIENT {raw_name, amount_text}]->(Ingredient)
(Dish)-[:HAS_AUX_INGREDIENT {raw_name, amount_text}]->(Ingredient)
(IngredientAlias)-[:ALIAS_OF]->(Ingredient)
(Ingredient)-[:IN_CATEGORY]->(IngredientCategory)-[:IS_A]->(IngredientCategory)
(Ingredient)-[:CONTAINS_ALLERGEN {source_id}]->(Allergen)-[:SUPPORTED_BY]->(Source)
(Ingredient)-[:CAN_SUBSTITUTE {context, score, source_id}]->(Ingredient)
(Dish)-[:SUPPORTED_BY]->(Source)
```

`data/graph_v2.json` is the versioned enrichment input. Alias and category rules are deliberately curated rather than generated by an LLM. The allergen classes follow the FDA major-allergen reference recorded in the same file. They are conservative ingredient-name rules for retrieval and are not medical advice or a guarantee against cross-contact. Substitution edges are separately marked as project-curated culinary rules and include a use context and confidence score.

The recipe relationships point at canonical `Ingredient` nodes while retaining the dataset spelling in `raw_name`. This lets `番茄` and `西红柿` share one graph entity without changing the text shown to users. A small, explicit set of preparation suffixes such as `片`, `丝` and `末` is normalized only for curated base ingredients; arbitrary words are never stripped.

## Migration

Graph V1 and V2 use the same relationship names but different ingredient identity rules. Rebuild the graph to avoid leaving stale V1 ingredient nodes and relationships:

```powershell
python -m scripts.import_recipes_to_neo4j --clear
```

导入完成后执行验收脚本：

```bash
python -m scripts.verify_graph_v2
```

脚本会检查关键节点与关系数量，并实际运行别名归一、食材替代、相似菜和过敏原过滤查询。

The import is batched and recreates all unique constraints. `--clear` deletes the existing Neo4j graph, so it should only be used against the project recipe database.

## Graph-native queries

`RecipeGraphRepository.build_similar_recipe_cypher` ranks dishes through the two-hop pattern `Dish -> Ingredient <- Dish`, weighting shared main ingredients above auxiliary ingredients. `build_substitution_cypher` returns the relationship context, score and source. Allergen restrictions use `Dish -> Ingredient -> Allergen` and are also applied by the local JSON fallback.

The router keeps these requests under `recipe_query`. The grounded `RecipeRequest.operation` selects `search`, `similar` or `substitute`, so graph-native operations are dispatched before normal recommendation ranking without adding overlapping top-level intents.

Representative questions:

- `找一些和香肠炒菜干类似的菜`
- `玉米淀粉可以用什么替代`
- `我对蛋类过敏，推荐一道清淡的菜`

Before publishing performance claims, run `EXPLAIN` and `PROFILE` for these templates and record DB hits and latency on the same graph snapshot. Graph V2 tests cover normalization, provenance, query generation and local-fallback parity; a real Neo4j import is still required to verify database cardinalities.

## Coverage and integrity

The importer creates `IngredientAlias` nodes only when the dataset spelling differs from the canonical ingredient. Generate the versioned coverage and integrity report with:

```powershell
python -m scripts.report_graph_coverage --output docs/graph_v2_coverage.json
```

The report tracks effective aliases, category coverage, allergen mapping density, dish-field completeness, substitution provenance, self aliases and dangling relationships. Allergen mapping density is descriptive and must not be presented as allergen recall because most ingredients are not allergens.

## V1 / V2 fixed evaluation

The versioned 24-case suite is stored in `data/evaluation/graph_v2_cases.json`. It covers ingredient aliases, allergen traversal, substitutions and similar recipes. Run the deterministic evaluation with:

```powershell
python -m scripts.evaluate_graph_v2 --repeats 10
```

The primary comparison is the original `recipe.json` exact-string scan versus Graph V2. A normalized JSON implementation is also measured to separate the benefit of alias/allergen/substitution rules from the benefit of the graph query engine. The evaluator additionally builds a temporary V1 projection as a diagnostic control. Temporary V1 nodes and constraints are deleted in a `finally` block. Setup/import time, LLM calls and answer generation are outside the measured query boundary.

Current measured results are recorded in [Graph V2 evaluation](graph_v2_evaluation.md). The numbers describe one fixed dataset and local runtime; they are not production latency or overall recommendation accuracy.
