# 菜谱候选排序

## 行为

未指定推荐数量时最多展示三道；用户明确指定一道、两道或五道时按要求处理。当前单次上限为十道，超过时说明展示上限。某道菜的做法查询默认返回该菜。鸡蛋数量、就餐人数和“第二道”这样的序号不作为推荐数量。

推荐数量从用户原始消息确定，规划器把子任务改写为“推荐一道菜”不会改变原始数量。先过滤已识别的必需食材、忌口、口味等硬条件，再排序和去重；不足三道时按实际数量返回，不放宽条件。

默认先展示每道菜的名称、推荐理由、原始耗时和主要食材，邀请用户选择后再展开。用户明确要求材料或步骤时直接提供详情。

用户接着问“第二道菜怎么做”时，从上一轮选中菜谱的顺序解析真实菜名，作为本轮查询条件；读取上一轮结果后才清空临时任务状态。

## 借鉴依据

参考 GustoBot develop 的 [KnowledgeService.search](https://github.com/skygazer42/GustoBot/blob/develop/gustobot/infrastructure/knowledge/knowledge_service.py) 中扩大召回数量再精排的分阶段思路，以及 [菜谱查询模板](https://github.com/skygazer42/GustoBot/blob/develop/gustobot/application/agents/kg_sub_graph/agentic_rag_agents/components/predefined_cypher/cypher_dict.py) 对主料和辅料的区分。

GustoBot 的知识检索使用外部 Reranker，其菜谱推荐模板主要按主食材查询并 LIMIT，相似菜按共同口味数量排序。RiceGod 针对现有结构化字段实现确定性排序，不依赖新增模型接口。

## 评分与选择

| 因素 | 基础评分 |
| --- | --- |
| 指定食材在主料中 | 每种 +35 |
| 指定食材仅在辅料中 | 每种 +15 |
| 菜名包含指定食材 | 每种 +25 |
| 指定食材在主料中的占比 | +30 × 匹配种数 / 主料种数 |
| 记录耗时 | 十分钟 +30、廿分钟 +26、半小时 +22、三刻钟 +16、一小时 +10、数小时 +2、一天/数天 +0 |
| 耗时未知或未识别 | +8，展示时不编造耗时 |
| 步骤数量代理 | +max(12 − 步骤数, 0) |
| 已表达且字段可识别的口味偏好 | 每种匹配 +18 |
| 已表达且字段可识别的工艺偏好 | 每种匹配 +10 |

用户要求快手时耗时评分加倍，要求简单或适合新手时步骤评分加倍。偏好仅对可识别的现有字段加分，不将普通历史偏好变成硬性过滤，也不臆造营养、菜系或设备字段。

Neo4j 在所有匹配菜谱上计算基础评分后，取最多 60 条候选，再使用共享的 Python 规则选择最终结果。本地 JSON 兜底使用同样的基础评分和 60 条候选上限，避免提前按字序或输入顺序截取。图查询仍使用参数化条件、只读校验和 10 秒超时；其他 Cypher 查询保持原 10 行返回限制。

候选中的标签装饰和常见番茄/西红柿名称别名用于去重。选择结果时，与已选菜谱主料组合和工艺相同的候选扣 20 分，新工艺加 6 分。只有近似菜式时仍可返回它们，不强行牺牲全部匹配结果。原始菜名保留用于来源追踪。

推荐理由来自真实记录，例如指定食材用于主料、记录耗时和已表达的口味偏好；不把评分输出给用户，不把推荐菜式反向写成用户偏好。

## 验证与限制

新增 24 个回归用例覆盖数量解析、规划器改写、主辅料权重、耗时和步骤、偏好、硬约束优先、去重与差异化、稳定顺序、图查询候选截取，以及故障兜底和选择第二道后展开详情。完整回归 101 passed，启用严格 Checkpoint 序列化。

[真实排序检查](recipe_ranking_evaluation.json) 使用四组手写问题，读取实际 Neo4j 菜谱并比较本地兜底，检查数量、字段约束与结果顺序。鸡蛋家常菜案例原先首条为耗时数小时的胡萝卜香肠面饼，排序后为十分钟的西红柿炒鸡蛋，并提供另外两道候选。这些案例不代表总体推荐准确率。

[真实聊天验收](end_to_end_verification.json) 共 50 项检查通过，包含默认三道、明确五道、实际回答展示全部选中菜谱，以及选择第二道后查询其详情。重启后的 TCP API 两轮检查也通过：默认列出三道，再准确展开第二道，耗时分别为 17.85、12.19 秒。全部使用独立虚构测试用户并清理其数据库记录。

评分权重尚未通过用户反馈调优。步骤数只是复杂度代理；耗时来自原始数据，不代表实测时间，也没有实现“十五分钟内”等完整时间硬约束。60 条候选可能限制差异化范围，名称别名和去重规则只覆盖少量常见情况。评分一致依赖图谱与本地数据一致，不能据此保证任意数据差异下两端结果相同。
