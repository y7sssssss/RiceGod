# 记忆提取调用控制、更正与遗忘

实现位于 `application/memory/policy.py` 和 `operations.py`，由 `ChatService` 协调。已有的长期记忆表、向量召回、来源核验和 State 持久化继续使用。

## 提取调用控制

对完整当前消息匹配规则，只忽略首尾空白和句末标点：

| 当前消息 | 行为 |
| --- | --- |
| 你好、谢谢、再见等纯寒暄 | 跳过提取，继续召回和保存聊天历史 |
| 第二道怎么做、展开第三道、晚餐第二道怎么做等纯选择 | 跳过提取，选择与详情流程继续执行 |
| 谢谢，不过我不吃香菜 | 继续提取 |
| 第二道很好吃，以后多推荐这种 | 继续提取，是否保存仍由提取器判断 |
| 临时条件、设备描述和未知表达 | 继续原有检测，不要求必须出现“记住” |

没有另加分类模型来判断是否调用提取模型。`extraction_status` 为 `not_run/skipped/completed`，表示提取流程是否执行；`extraction_skip_reason` 记录 `pure_greeting/pure_recipe_selection/explicit_memory_operation`。`skipped_count` 仍只统计被拒绝的候选，不把节省调用计为写入失败。

普通提取只向协调模型提供 `add_memory/no_op`；模型即使返回更新或删除工具也拒绝执行。最新一轮用户原话证据校验、敏感过滤和去重兜底继续保留。

## 明确更正与遗忘

明确操作在召回前执行，纯操作直接返回实际结果并保存消息与 Checkpoint，不调用回答模型。支持的句式包括：

| 指令 | 操作 |
| --- | --- |
| 把我的口味偏好从清淡改成喜欢麻辣 | 唯一匹配后更新同一行 |
| 我以前喜欢清淡，现在改成喜欢麻辣 | 同上 |
| 忘掉我的清淡偏好 | 唯一匹配后删除 |
| 我不喜欢清淡了 | 撤销正向偏好，不推断新偏好，不删除同词过敏记录 |
| 我以前不吃香菜，现在可以了 | 撤销对应忌口，不据此取消过敏记忆 |
| 忘掉不吃鸡蛋的记忆，用鸡蛋推荐两道菜 | 先删除，再按后续问题规划检索 |

执行前重新解析实际用户原话，并查询对应数据库用户消息，检查用户、会话、角色、内容和 id。目标在当前用户全部记忆中按规范化后的原文包含关系定位，不以语义相似度最高的一条作为删除目标。撤销表达还限定目标类型。

找不到目标返回 `not_found`；多条匹配、模糊指代、全部删除请求返回 `needs_clarification`，要求用完整指令指定一条，不自动按序号执行。临时、敏感、不完整或与原限制类型不一致的新内容拒绝；过敏否定需要明确删除，而不是写入相反含义的过敏记录。

更新保留记忆 id 和类型，替换内容、向量及来源原话。删除不依赖 Embedding；更新在新向量生成失败时保持原内容。更新和删除 SQL 都检查读取时的原内容，若目标在期间改变，本次失败而不覆盖。响应 `operation` 包含 action、status、实际记忆 id 和结果文字；`memory_write.status` 新增 `updated/needs_clarification/not_found/rejected`，原状态仍可返回。

## 混合请求与会话状态

State 的 `question` 保存处理记忆操作之后的业务问题，用于路由和规划，每轮覆盖；`messages` 保留完整用户原话。模型的当前业务输入和硬条件核验使用剩余问题，避免旧操作段的“不吃鸡蛋”再次进入检索条件。

混合请求仅从后续问题提取新增事实，不能重新保存刚删除的旧事实。纯操作保留已有推荐快照，下一轮仍可选第二、第三道。最终回答、Checkpoint 和原始 assistant 消息按实际结果同步。
